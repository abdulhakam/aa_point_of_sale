# Plan: Fix companies2parties Many-to-Many Relationship Logic and Workflow

## Problem Analysis
The current implementation in `UpdatePartyForm` and `UpdateCompanyForm` always deletes all existing associations and inserts all new ones, regardless of what changed. This is inefficient and doesn't match the desired behavior of only updating differences.

Additionally, the management tables don't display the relationships, making it hard to see associated companies/parties at a glance.

## Goals
1. Implement efficient association updates that compare previous vs. new selections and only insert/delete differences.
2. Add columns to the parties and companies tables to display associated entities.
3. Ensure the UI updates seamlessly after changes.

## Implementation Steps

### 1. Fix UpdatePartyForm Logic
- **File**: `frontend-tb/src/routes/app/management/parties/-UpdateParty.tsx`
- **Changes**:
  - Compute added companies: `values.companies` minus `currentCompanies`
  - Compute removed companies: `currentCompanies` minus `values.companies`
  - Only delete associations for removed companies
  - Only insert associations for added companies
  - If no changes to companies, skip association updates entirely

### 2. Fix UpdateCompanyForm Logic  
- **File**: `frontend-tb/src/routes/app/management/companies/-UpdateCompany.tsx`
- **Changes**:
  - Similar logic: compute added/removed parties
  - Only update associations that changed
  - Skip if no changes to parties selection

### 3. Add Companies Column to Parties Table
- **File**: `frontend-tb/src/routes/app/management/parties/index.tsx`
- **Changes**:
  - Add "Companies" to `tableStructure`
  - Modify the useLiveQuery to include associations
  - Since many-to-many causes duplicates, process data to group by party and collect company names
  - Display as comma-separated list or badges

### 4. Add Parties Column to Companies Table
- **File**: `frontend-tb/src/routes/app/management/companies/index.tsx`  
- **Changes**:
  - Add "Parties" to `tableStructure`
  - Similar query modification and data processing
  - Display associated parties in the table row

### 5. Testing and Validation
- Test creating/updating parties with company selections
- Test creating/updating companies with party selections
- Verify associations are correctly inserted/deleted
- Ensure table displays update correctly
- Check performance with large datasets

### 6. Edge Cases
- Handle empty selections (remove all associations)
- Handle adding/removing multiple associations
- Ensure no duplicate associations are created
- Handle concurrent updates if multiple users edit simultaneously

## Technical Considerations
- Use Set operations for efficient diffing of arrays
- Maintain optimistic updates for better UX
- Ensure foreign key constraints are respected
- Consider adding loading states for association updates</content>
