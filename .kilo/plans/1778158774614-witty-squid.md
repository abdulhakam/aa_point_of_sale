# Plan: Replace Collections Usage with trailbaseClient and TanStack Query in All Management Pages

## Goal
Replace the use of collection objects (e.g., `sectionsCollection`, `areasCollection`, etc.) from `@frontend-tb/src/collections/` with direct usage of `trailbaseClient` and TanStack Query hooks in all management pages under `frontend-tb/src/routes/app/management/` (areas, categories, companies, order_bookers, parties, products, sections) and their subcomponents.

## Current State Analysis
Each management entity (areas, categories, companies, order_bookers, parties, products, sections) has:
- `index.tsx`: Uses `useQuery` with `trailbaseClient.records(entity).list()` for fetching data. Uses `{entity}Collection.delete()` for deletions.
- `-Create{Entity}.tsx`: Uses `{entity}Collection.insert()` for creating new records.
- `-Update{Entity}.tsx`: Uses `{entity}Collection.update()` for updating records.
- Collections provide optimistic updates, but the current code disables them with `{ optimistic: false }`.
- Sections have already been updated as per previous implementation.

## Proposed Changes
For each management entity (areas, categories, companies, order_bookers, parties, products; sections already done):
1. **Remove Collection Imports**: Eliminate imports of `{entity}Collection` from all files in the entity directory.
2. **Replace Insert Operation in -Create{Entity}.tsx**:
   - Use `trailbaseClient.records("{entity}").create()` instead of `{entity}Collection.insert()`.
   - Wrap the operation with `useMutation` from TanStack Query for better state management (loading, error handling).
3. **Replace Update Operation in -Update{Entity}.tsx**:
   - Use `trailbaseClient.records("{entity}").update()` instead of `{entity}Collection.update()`.
   - Use `useMutation` for the update operation.
4. **Replace Delete Operation in index.tsx**:
   - Use `trailbaseClient.records("{entity}").delete()` instead of `{entity}Collection.delete()`.
   - Use `useMutation` for the delete operation.
5. **Add Mutation Hooks**: Import and use `useMutation` from `@tanstack/react-query` in the components where mutations occur.
6. **Maintain Loading States**: Update loading state management to use mutation's `isPending` or similar.
7. **Error Handling**: Add proper error handling using mutation's `error` state and Mantine notifications to report errors to the user.
8. **Query Invalidations**: After successful mutations, use `queryClient.invalidateQueries(["{entity}", "all"])` to refresh the entity list and keep the frontend up to date with the latest data from the backend.
9. **No Optimistic Updates**: As per user preference, do not implement optimistic updates; rely on query invalidations for data freshness.
10. **Loading States**: Disable buttons during mutation loading states.
