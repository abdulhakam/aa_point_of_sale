# Plan: Replace fetch with Trailbase API Client in Management Index

## Overview
Replace the direct `fetch` API calls in `frontend-tb/src/routes/app/management/index.tsx` with the official Trailbase API client implementation. The current code fetches full record arrays just to get counts, which is inefficient. We'll use the client's `list()` method with `count: true` to get total counts without downloading all data.

## Current Implementation Analysis
- Uses `useQueries` with `fetch` to call `http://localhost:4000/api/records/v1/${entity.key}`
- Downloads entire record arrays and uses `data?.length` for counts
- Has optimization comment suggesting `/count` endpoint, but we'll use client's built-in count feature

## Proposed Changes

### 1. Import Trailbase Client
- Add import: `import { trailbaseClient } from "../../../trailbaseClient";`
- Remove dependency on direct fetch calls

### 2. Update Query Functions
- Replace `queryFn` in `useQueries` to use `trailbaseClient.records(entity.key).list({ pagination: { limit: 0 }, count: true })`
- Extract `response.total_count` as the data

### 3. Update Data Display
- Change count display from `${data?.length ?? 0} items` to `${data ?? 0} items`
- Since `data` is now the count number directly

### 4. Code Cleanup
- Remove the optimization comment since we're now using efficient counting
- Consider removing unused collection imports if not needed elsewhere

## Benefits
- More efficient: Gets count without downloading full record data
- Uses official client: Better integration with Trailbase ecosystem
- Cleaner code: Leverages TypeScript types and proper API abstraction
