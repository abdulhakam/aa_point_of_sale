{# Quick-create panels: a party or an item made without leaving the invoice. ================================================================================ A macro rather than a dialog because the panel must live INSIDE the form it serves — the create rides in the same submit as the change that needed it (the invoice's header, or the line being added). That is what keeps the whole thing a form post: no fetch, no second request, no lost edits. The "Create …" row in the combobox points here through the select's `data-create` attribute, and `app/public/js/autocomplete.js` opens the panel and puts the typed name in. The panel is hidden and its controls DISABLED until then, so a plain submit carries none of these field names — which is why the routes can key off "party_new_name is non-empty" with no marker field to remember to clear. ⚠️ There is deliberately no `required` in this markup. A hidden, required input still blocks form submission — the browser validates it even though nobody can see it — so the header form would have been unsubmittable with JavaScript off. The combobox sets `required` on the name when it opens the panel, and the server checks it again. #} {% macro party(type, areas) -%}
