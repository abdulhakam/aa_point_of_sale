`frontend/` 1136 MB, `guests/` 443 MB, `.git/` 254 MB, `backend/` 214 MB,
`.kilo/` 107 MB. `git status --porcelain` was clean, so every candidate below is
either a rebuild artifact or an ignored/untracked path.

## Recoverable but not free to lose

- `trailbase/traildepot/runtime/` (~90 files) — verified byte-identical to
  `trailbase/runtime/` (same file set, same `compute/reports.js` hash
  `201501D4…`), which **is** tracked in git. So the deployed copy is
  regenerable by the copy step, but deleting it stops the running guest.
- `trailbase/traildepot/{config,metadata}.textproto` — mirrors of
  `trailbase/src/*.textproto` (also tracked).

## Do NOT delete

- `trailbase/traildepot/data/main.db*` (189 MB) — the live migrated production DB.
- `trailbase/traildepot/secrets/keys/*.pem` — token verification keys; regenerating
  them invalidates every issued session.
- `trailbase/traildepot/migrations/main/*.sql` — authored migrations, git-ignored
  but not present anywhere else in the repo.
- `backend/p_data/` (68 MB) — committed, and `trailbase/tools/extract-legacy-views.mjs`
  and `verify-legacy-views.mjs` both read `backend/p_data/data.db` (both tools deleted 2026-10-02
  with the legacy view layer; the directory is the legacy source data regardless). See
  [[pocketbase-data-dirs-in-git]] for the separate decision to untrack it.
- `backend/pb_data/data.db` (11 MB) — legacy production data.
- `vault/credentials/` — plaintext secrets; do not commit (see build-and-run).
- `frontend/node_modules/` and `guests/node_modules/` (1112 MB combined) — only delete
  if you accept a full reinstall.

## Largest win first

`cargo clean` in `trailbase/host` alone frees 2.4 GB, which is more than every
other candidate combined.
