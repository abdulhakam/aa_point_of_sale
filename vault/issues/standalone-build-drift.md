# Issue — Standalone Build Drift

## Summary

The committed `standalone/` directory is a **prebuilt Next.js standalone artifact that does
not match the current frontend source**. It ships report pages the source does not have and
was built from a different checkout. `RUN MINI.BAT` runs this stale server, so "minimal run"
behaves differently from the source.

## Evidence (observed 2026-09-19)

- Compiled report routes:
  - `standalone/.next` exposes **18** report routes, including `dailysale`, `outstanding`,
    and `productsale`.
  - The current source (`frontend/src/app/app/reports/**`) and its build
    (`frontend/.next`) expose **15** routes and contain none of those three.
- Different build IDs: `frontend/.next/BUILD_ID` = `sBqoBfqtHYxCW2lKiK5Wy` vs
  `standalone/.next/BUILD_ID` = `7yfGbD4Kt-F4gx9UhwMZg`.
- `standalone/server.js` embeds `outputFileTracingRoot` pointing at
  `D:\...\WORK\WORK\ERP_DB\production\aa_point_of_sale\frontend` — a **different checkout**
  than this `PRODUCTION_FULL` copy.
- `standalone/package.json` lacks the `tauri` script and the `@tauri-apps/cli`
  devDependency that `frontend/package.json` has, so it predates the Tauri work.

## Impact

- The "mini" run path serves an unknown revision of the UI — a correctness/support risk.
- Report availability differs depending on launch mode, which is confusing.
- A rebuild cannot be reproduced from source without knowing the originating revision.

## Likely cause

`standalone/` is a build output that was copied in from another working copy
(`...\WORK\WORK\ERP_DB\production\...`) and is not regenerated by any script in this repo.

## Options

1. Rebuild `standalone/` from this source and replace the stale artifact
   (`next build` with `output: 'standalone'`, then copy `.next/standalone`, `.next/static`,
   and `public`).
2. Remove `standalone/` and make `RUN MINI.BAT` use the normal build/run path.
3. Pin the intended revision and document why the extra report pages exist.

## Workaround

Use `RUN.BAT` (source build) rather than `RUN MINI.BAT` until reconciled.

## Update (2026-09-20) — the extra-report discrepancy is resolved

Re-checked against the current checkout: **the source now has all three reports.** They were
added by commit `261a56c` ("Introduce new reporting pages for daily, outstanding, and product
sales, and add a reusable Select component"), `reports/page.tsx` links all three, and the
current `frontend/` build emits 18 report routes — the same count this Issue attributed to
`standalone/`. The Evidence bullet claiming the source "contain[s] none of those three"
was written from a stale observation and is **withdrawn**.

What remains of this Issue is the build-artifact drift only: a different `BUILD_ID`, a
`server.js` tracing root pointing at another checkout (`...\WORK\WORK\ERP_DB\production\...`),
and a `package.json` that predates the Tauri work — i.e. `standalone/` is still not
regenerated from this source (see [[Reconcile the standalone build with source]]).

A follow-up consequence: those three pages had never been through
[[POS-0015 Trim expands + adopt pagination in report pages]], so they still over-fetch — tracked
as [[POS-0025 Optimize + verify the Daily Sale, Outstanding, and Product Sale reports]].
