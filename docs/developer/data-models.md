# AA Point of Sale — Developer Documentation: Data Models & Database Schema

## Database Overview

- **Engine:** SQLite (STRICT tables only)
- **Location:** `traildepot/data/main.db`
- **Primary Keys:** UUIDv7 BLOB (16 bytes), generated by `uuid_v7()`
- **Timestamps:** TEXT in PocketBase format `'%Y-%m-%d %H:%M:%fZ'`
- **Foreign Keys:** Enforced (`PRAGMA foreign_keys=ON`)
- **Enumerations:** INTEGER codes backed by lookup tables (never TEXT/JSON)
- **Soft Delete:** `deleted INTEGER NOT NULL DEFAULT 0 CHECK (deleted IN (0,1))`

### Enumeration Tables (Vocabularies)

#### `party_types`

## Triggers

Every table has an `AFTER UPDATE` trigger to maintain `updated` timestamp:

```sql
CREATE TRIGGER trg_<table>__updated AFTER UPDATE ON <table> FOR EACH ROW
BEGIN UPDATE <table> SET updated = strftime('%Y-%m-%d %H:%M:%fZ','now') WHERE id = OLD.id; END;
```

Tables with triggers: `party_types`, `invoice_types`, `payment_types`, `sections`, `categories`, `companies`, `areas`, `parties`, `order_bookers`, `items`, `expenses`, `party_companies`, `order_booker_companies`, `invoices`, `invoices_return_reference`, `transactions`, `payments`.

## Data Conventions

### ID Encoding
- **Storage:** 16-byte BLOB (UUIDv7)
- **Transport:** URL-safe base64 (22 chars, no padding)
- **Alphabet:** `ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789-_`
- **SQL:** `unhex(?)` for queries, `hex()` for output

### Money Handling
- **Storage:** REAL (full precision)
- **Display:** 2 decimal places (paisa)
- **Arithmetic:** Integer paisa (×100, round half-up, ÷100)
- **Rule:** Round PER LINE before summing (see `prelude.sql` `line_totals` CTE)

### Dates
- **Business date:** `invoices.dated` (operator-entered, falls back to `created`)
- **Payment date:** `payments.payment_date` (falls back to invoice's dated, then payment's created)
- **Created/Updated:** PocketBase format `'%Y-%m-%d %H:%M:%fZ'`
- **Empty string `''`** means "not set" — not NULL

### Soft Delete Pattern
- `deleted INTEGER NOT NULL DEFAULT 0 CHECK(deleted IN (0,1))`
- Queries filter `WHERE deleted = 0`
- Hard delete not used; referential integrity via FK constraints

## Reference Data (refs.sql)

The `refs.sql` file defines the reference lists used by dropdowns and pickers:

```sql
SELECT 'sections' AS ref_key, 'sections' AS table_name
UNION ALL SELECT 'companies', 'companies'
UNION ALL SELECT 'areas', 'areas'
UNION ALL SELECT 'parties', 'parties'
UNION ALL SELECT 'bookers', 'order_bookers'
UNION ALL SELECT 'items', 'items'
UNION ALL SELECT 'partyTypes', 'party_types'
UNION ALL SELECT 'invoiceTypes', 'invoice_types'
UNION ALL SELECT 'paymentTypes', 'payment_types';
```

**Key mappings:**
- `bookers` → `order_bookers` table
- `partyTypes` → `party_types` table
- `invoiceTypes` → `invoice_types` table
- `paymentTypes` → `payment_types` table
- **No `categories`** — legacy categories map to `companies`
